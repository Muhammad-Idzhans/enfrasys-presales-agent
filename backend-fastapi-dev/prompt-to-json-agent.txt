## STEP 2 — Feasibility Verdict

Recommendation: CONDITIONAL GO (pursue with competitive proposal) — see rationale below.

- Fit with Enfrasys strengths
  - Good fit. Enfrasys’ Microsoft-first strengths (Azure, Microsoft Foundry / Document Intelligence, Power Platform, M365 / SharePoint integration, Azure AD SSO, Fabric for analytics) map directly to almost all EPF functional and technical requirements.
  - Microsoft Document Intelligence (Document Understanding/form extraction) supports custom model training, key-value/table extraction, confidence scoring, and HITL patterns (via orchestration + UI), and Foundry/AI Search can support knowledge/LLM context features. Azure platform provides required security controls (Key Vault for CMK/BYOK, Azure AD for SSO, role-based access control, regional deployment).

- Can this be delivered with a Microsoft-first stack?
  - Yes. A Microsoft-first architecture can cover all major requirements:
    - Document extraction: Azure AI Document Intelligence (Form Recognizer successor).
    - Storage: Azure Blob Storage (secured with encryption, access controls).
    - Secrets: Azure Key Vault (BYOK).
    - Authentication/SSO: Microsoft Entra / Azure AD (MFA via Microsoft Authenticator).
    - HITL UI: ASP.NET / Azure App Service or Azure Container Apps / Azure Front Door with storage backend (or Power Apps for light UI but custom web application preferred for performance).
    - Workflow/orchestration: Azure Logic Apps / Azure Functions / Azure Durable Functions.
    - Search/LLM contextualization: Azure AI Search (Foundry IQ) and Azure OpenAI or Foundry models (subject to EPF AI governance).
    - Monitoring and dashboards: Azure Monitor / Application Insights / Power BI (or Microsoft Fabric for advanced analytics).
    - Integration: Secure SFTP (Azure SFTP on Blob via SFTP support or Azure File Storage + gateway) and REST APIs via Azure API Management.
  - All above components are GA / actively supported (sources cited in STEP 3).

- Are the timeline and mandatory requirements realistic?
  - Timeline: Aggressive but feasible. Five months total (Dev/UAT/Prod + interfaces + POC + integration) is realistic if:
    - EPF provides EMS/ECM flatfile formats and test endpoints early.
    - Vendor has prebuilt connectors and IDP templates (document types) to accelerate training.
    - Dedicated Enfrasys project team and EPF SMEs are available (fast sign-offs).
  - Mandatory requirements: Must secure principal partner certification/back-to-back support (Microsoft partner status + Azure competency) and produce ISO/SOC attestations. Enfrasys must confirm partnerships and provide required security evidence.

- Key risks
  1. Data residency / PDPA & PII constraint: RFP mandates PII not be stored in cloud — architecture must perform extraction in a processing model that prevents persistent PII in cloud storage (use transient processing, mask/minimize storage). This complicates typical SaaS IDP flows and requires careful design (e.g., tokenization on ingest, ephemeral storage, encrypted temporary blobs with automated purge).
  2. Integration with legacy EMS/ECM (Newgen OmniDocs): flatfile format and transfer timing may need multiple iterations; offline continuity requirements mean queueing and reconciliation flows must be tested thoroughly.
  3. SLA penalties and LADs are severe (10% of annual contract value *12 months; LAD formula with minimum RM1,000/day). Delivery & ops runbook must mitigate these risks (sufficient HA, monitoring, runbooks, capacity planning, disaster recovery).
  4. EPF AI governance — LLM usage restricted; vendor must ensure no training on EPF data without consent and provide attestations.

Conclusion: Pursue the opportunity if Enfrasys can provide:
- Microsoft partner evidence and principal back-to-back support (obligatory).
- Clear architecture addressing PII residency (transient processing or in-country tenant + encryption + BYOK).
- A realistic fixed-price implementation with contingency and a scalable subscription model.
